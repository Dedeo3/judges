## Aturan wajib
1. **Jangan pernah** menaruh private key, seed, token, atau secret di repo, chat grup, atau screenshot. Key deployer diberikan lewat `--keystore` / `--ledger`, bukan env.
2. File env (`contracts/.env`, `apps/web/.env.local`) di-gitignore dan tidak ada di repo. Buat sendiri dari `.env.example`.
3. `JUDGES_DOMAIN_SECRET` production dipegang **satu orang**, di-backup, dan **tidak boleh dirotasi**. Rotasi membuat semua passkey dan nullifier tidak valid.
4. Semua passkey yang didaftarkan sebelum redesign B deploy harus **daftar ulang** sesudahnya. Beri tahu integrator soal ini.
5. **Klaim harus jujur.** Judges membuktikan "pemegang passkey hadir", **bukan** "manusia unik". Registrasi saat ini `attestationType: "none"` tanpa rate limit, jadi satu orang bisa punya banyak passkey. Jangan bilang anti-sybil penuh.
6. Fixture test dibuat lewat script, bukan disalin manual. Sebutkan dengan jelas apa yang belum diverifikasi.

## Tugas 2: Redesign B, supaya backend tidak jadi titik sentral
**Timebox:** 6 hari kerja, target 26 Sep. **Jika lewat:** stop dan submit versi sekarang + disclosure yang sudah ada di README §27.8.

**Masalah sekarang**
- `credentialSecret = HMAC(JUDGES_DOMAIN_SECRET, credentialId ‖ publicKey)` diturunkan di server.
- Akibatnya backend bisa menghitung nullifier siapa pun dan menautkan aktivitas user.

**Desain B**
- **Secret dibuat di client.**
  - Sumber utama: signature wallet deterministik atas pesan tetap, lalu di-hash ke field.
  - WebAuthn PRF hanya upgrade opsional. Dukungannya belum merata, dan belum terbukti output-nya sama antar-device.
- **Commitment:** `identityCommitment = Poseidon(secret)`. Server hanya menyimpan commitment.
- **Tree:** server menyusun LeanIMT (zk-kit) off-chain, lalu mem-post root ke kontrak. Kontrak menyimpan **root history** supaya proof dengan root yang sedikit lama tetap valid.
- **Circuit baru**
  - Isi: membership Merkle depth 20 + `nullifier = Poseidon(secret, applicationIdHash, epoch)`.
  - Binding wallet/aksi tetap lewat public input, seperti sekarang.
  - Trusted setup baru pakai ptau 2^14, lalu re-export `JudgesGroth16Verifier.sol` dan fixture test.
- **Proving di browser** (snarkjs). `/api/prove` di server dihapus atau tidak dipakai lagi.
- **API publik SDK** (`register` / `prove` / `verify`) dipertahankan supaya integrator tidak perlu mengubah kode.
- **Setelah selesai:** semua test + E2E popup hijau, lalu redeploy (kontrak + web).

**Yang sudah diukur** (M1, circuit percobaan)

| Circuit | Constraint | Proving browser | zkey |
|---|---|---|---|
| Sekarang | 1,2k | ~115 ms | 0,55 MB |
| Membership depth 20 | 11,4k | ~680 ms | 4,9 MB |

- PoseidonT3 (`poseidon-solidity` 0.0.5) cocok dengan circomlib/poseidon-lite.
- Gas insert LeanIMT **on-chain** di Monad: rata-rata ~609k, terburuk ~897k. Karena mahal, tree dibuat off-chain (opsi registrasi penuh on-chain sudah ditolak).
- Verifikasi Groth16 per aksi di Monad sekarang ~1,13M gas. Tidak berubah signifikan dengan B.

**Wajib diukur dan dilaporkan di `IMPLEMENTATION.md`**
- Waktu proving di HP nyata (Android menengah + iPhone). CPU throttling di Chrome **tidak** valid karena tidak memperlambat Web Worker.
- Gas tx post root.
- Apakah signature deterministik di wallet yang kita dukung. Smart wallet / MPC mungkin tidak.

**Keterbatasan yang tetap ada (tulis di README):** server masih bisa menyensor atau menambah leaf. B tidak menambah sybil resistance.
